== Introduction and goals

=== Requirements

The purpose of this project is to develop a full-stack web application for a game named Y, communicating human players and automated agents. The following specifications must be in the final version of the aplication:

==== User Management
[cols="1,4"]
|===
| ID | Description
| FR-01
| The system must allow users to register and authenticate (login/logout) to manage their personal  profiles.
| FR-02
| The system must maintain a persistent history of matches played by each registered user.
| FR-03
| The system must provide a profile for users to view their statistics, including win/loss ratios and total games played.
|===

==== Gameplay (Web Frontend)
[cols="1,4"]
|===
| ID | Description
| FR-04
| The frontend should implement the "Classic Version" of Game Y in a Player-vs-Machine (AI) mode.
| FR-05
| The system must support variable board sizes, allowing the player to define the dimensions before starting the game.
| FR-06
| The UI should allow the player to select from multiple game strategies or difficulty levels provided by the AI.
|===


==== Game Engine (Python Module)
[cols="1,4"]
|===
| ID | Description 
| FR-08
| The module shall provide a real-time game interface for receiving player moves, updating the board state, and broadcasting the resulting game state to connected clients.
| FR-09
| The game engine shall validate the current board state after each move and determine whether the match has been won or continues in progress.
| FR-10
| The engine shall implement at least two distinct move-generation strategies for the AI and select the appropriate strategy based on the current game state.
|===

==== Quality goals
[cols="1,4"]
|===
| ID | Description 
| Availability
| The web application and WebSocket API shall be publicly reachable over HTTPS and maintain high availability
| Usability
| The frontend should be intuitive, allowing users to easily choose between game strategies and view their statistics and history without a challenging learning process.
| Performance
| The backend architecture must handle concurrent matches from both web users and API-based bots without significant latency.
| Security
| User data and match histories must be protected via secure authentication, ensuring users can only manage their own profiles
|===
